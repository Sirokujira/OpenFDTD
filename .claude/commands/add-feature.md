新機能「$ARGUMENTS」を、このプロジェクトの規約どおりに追加してください。

## 1. 対応範囲を先に決める

**CPU (`sol/`) / MPI (`mpi/`) / CUDA (`cuda/`) のどこまで対応するか**を最初に
決めて合意を取ってください。CPU のみにする場合も、それは正当な選択です
(既存の `tpa` がそうです) — ただし README への明記が必須になります。

`.claude/rules/build-targets.md` を読み、決めた範囲に応じて CMakeLists の
どのリストに手を入れるかを先に把握してください。**CI は CPU 版しかビルド
しないので、ここを間違えると誰も気付きません。**

## 2. 検証の当てを先に決める

実装前に、次を明示して合意を取ってください。

- どの解析解・文献値と比較するか
- その値の導出 (公式・代入値・数値)
- 妥当な許容誤差とその根拠

既存の `data/sample/tpa_slab.ofd` が良い雛形です (解析解
`T = 1/(1 + β I0 L)` の導出をコメントに持ち、振幅 3 点を ±7% で比較)。

比較先が見つからないなら、**極限値** (低周波・粗いメッシュ →∞) や
**既存経路との相互検証** を探してください。それも無ければ、定量検証できない
旨を先に伝えてから実装に入ってください。

## 3. 入力キー

`sol/input_data.c` に追加。既定値はキー省略時に従来動作と完全一致させる。
**`ofd_post` が新キーを無害に無視できることを実際に確認する**。

## 4. 実装

`.claude/rules/portability.md` に従う。特に VLA 禁止・OpenMP インデックスの
事前宣言・float\*/double\* の取り違えに注意。

## 5. 検証ケースと CI

`data/sample/` に .ofd と判定スクリプトを追加し、CI の 3 ジョブすべてに
ステップを足す。**Windows ジョブは PowerShell で判定を書き直している**ので、
期待値の二重管理に注意 (`.claude/rules/features.md` 参照)。

## 6. ドキュメント

README に機能説明と **CUDA/MPI 対応状況**を明記。新たに踏んだ移植性の
落とし穴は `.claude/rules/portability.md` に追記する。

## 7. 点検

`/preflight` を実行し、全項目 OK を確認してから報告してください。
